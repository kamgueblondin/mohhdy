# Lot 67 plan and result: real Internet in Mohhdy, bandwidth estimator

Branch `cursor/lot67`, base `origin/main` b1dbad1.

## Part 1: real HTTP/HTTPS from Ring 3

### What is real
- `userspace/wf_http.c`: URL parse/resolve/format, GET builder, incremental
  response parser (Content-Length, chunked, close-delimited, size cap).
- `userspace/wf_dns.c`: DNS query/answer codec (CNAME chains, pointer loop
  guard). Queries go over TCP to the lease DNS (slirp 10.0.2.3).
- `userspace/wf_tls.c`: TLS 1.2 client. ECDHE with X25519 only, suites
  ECDHE-ECDSA-AES128-GCM-SHA256 (c02b) and ECDHE-RSA-AES128-GCM-SHA256
  (c02f), extended master secret required, SNI, server key exchange
  signature checked (RSA PKCS#1 v1.5 / PSS, ECDSA P-256/P-384).
  supported_groups also lists P-256/P-384: a TLS 1.2 server needs it to
  pick an ECDSA certificate, the key exchange itself stays X25519.
- `userspace/wf_x509.c` + `wf_bn.c`, `wf_ec.c`, `wf_rsa.c`, `wf_sha512.c`:
  DER parser, chain build to a root of `/etc/ca-roots.pem` (37 public roots,
  generated by `scripts/lot67_ca_roots.sh`), signature checks, basic
  constraints, key usage, unknown critical extension refused, SAN host
  match (wildcard one label, IP SAN), validity dates checked when the RTC
  year is >= 2025; otherwise the report says `dates NOT checked`.
- `userspace/wf_fetch.c`: at most 5 redirects, https->http refused.
- `userspace/wf_guest.c`: guest transport over the socket syscalls
  (connect/send/receive/close relayed to the Ring 3 networker), RDRAND
  entropy (fallback `weak-tsc`, reported), DHCP on demand when no lease.
- `userspace/wf_html.c`: reader view for real pages (scripts, styles, SVG,
  forms, event attributes and non-web links dropped; links absolute;
  `[page tronquee]` at the budget). Not a full browser: no JavaScript, no
  site CSS.
- `userspace/shell_fetch.c`: `fetch [-v] [-I] [-raw] [-n N] URL` and
  `http-get` in the shell; the GUI `web URL` uses the same
  `shell_fetch_page` path (one code path).

### Root causes fixed (old stall at "attente de trame TLS" / FIN_WAIT_1)
1. A segment that did not fit the receive buffer moved the sequence before
   the space check: bytes were lost. Space is now checked first and a dup
   ACK is sent.
2. A fixed 65535 window was advertised over a 1 KiB buffer. The window is
   now the real free space (buffer 4 KiB), with a window update on read.
3. The receive window only shrank, so a connection died after 64 KiB.
4. Off-link peers had no next hop: ARP for the gateway, cached under the
   peer IP (`routed` counter).
5. After a FIN that arrived with the last data, a drained socket reported
   a timeout instead of end of stream (`peer_finished`).
6. `net-if dhcp` did nothing when the interface had no lease at all.

## Part 2: remaining partial US

- US-068 / US-073 (partial, closer): `userspace/p2p_bwe.c` is a
  model-based bandwidth estimator and pacer (delivery-rate samples,
  windowed max bottleneck bandwidth, windowed min RTT, STARTUP / DRAIN /
  PROBE_BW / PROBE_RTT, pacing = gain x bandwidth, cwnd = 2 BDP,
  app-limited samples do not lower the estimate). Unit tests against a
  simulated bottleneck: converges within 12 %, follows a drop to 1/4 and a
  rise, bounded queue, PROBE_RTT after a stale minimum. Mesh: `p2p-probe
  PEER [N]` sends a paced probe train, `p2p-bwe` reports; QEMU p2p
  scenario 1b runs 24 probes, all acked. Honest limit: in QEMU the RTT
  is below the 10 ms tick, so the guest estimate reflects poll scheduling,
  not a real link; the data path (`admit`) still uses the AIMD window, the
  estimator does not drive it yet. Still partial.
- US-076 (ARM port), US-080 (form factor layout), US-081 (power profiles
  without a battery): not changed in this lot. Still partial.
