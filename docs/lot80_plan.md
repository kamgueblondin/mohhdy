# Lot 80 plan: percentage tracks, percentage gaps, justify-content stretch

Base: origin/main bbf2ede (lot 79 merged as #236). Taken from the lot 79 first gap.

## Scope
1. Percentage grid tracks: `grid-template-columns/rows`, `grid-auto-columns/rows`,
   `repeat(N, P%)`, `repeat(auto-fill|auto-fit, P%)`, `minmax(P%, ...)`,
   `minmax(..., P%)`, `fit-content(P%)`. Stored as `WE_TRACK_PCT - P` (P 0..2000),
   resolved at layout against the grid content box (`track_base`): columns against
   the inline size, rows against a definite block size. Indefinite: size -> auto,
   floor -> 0, cap -> none. A percentage max below its floor resolves to the floor.
2. Percentage gaps: `row-gap`, `column-gap`, `gap` with plain `P%` for grid and
   flex. Column gap resolves against the inline size; row gap against a definite
   block size, else 0. Intrinsic sizing treats a percentage gap as 0.
   `calc()` gaps with a percentage remain refused.
3. `justify-content: stretch` (and `place-content: X stretch`): accepted. In grid it
   grows auto-max column tracks equally (as align-content does for rows); in flex it
   behaves as `flex-start`.
4. Already correct and locked by tests: flex gap with space-between/around/evenly,
   column flex row-gap, wrap + align-content distributions, align-content stretch,
   basic subgrid. Masonry: out of scope (not trivial).

## Review points
- Converted refusals: lot 57 `minmax(10%,1fr)` / `fit-content(10%)` and lot 55
  `column-gap:10%` now resolve instead of being refused; those tests assert the new boxes.
- New node fields `track_base[2]`, `gap_pct[2]` (we_doc_t stays < 1 MiB).
- Multicol `column-gap: P%` uses 0 (not resolved).
- Behavior fix: `align-content: stretch` now grows only auto rows; implicit rows sized by
  `grid-auto-rows: Npx` or `P%` were previously treated as stretch receivers.
- `fit-content(P%)` follows the engine's existing `fit-content(Npx)` rule (track clamps to
  the resolved limit), and `minmax(Npx, P%)` next to `1fr` keeps its floor, as with px caps.
- Tests are generated by run/lot80/gen/gen.py from an independent model (not committed).
