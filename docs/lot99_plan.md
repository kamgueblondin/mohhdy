Base: c3f691d (origin/main). PR 256 (the Lot 98 branch, head 30e0ea0)
is merged into origin/main (merge commit c3f691d), so the branch starts
from origin/main. Branch cursor/lot99. One guest engine
(userspace/webeng.c, unchanged here) and one shell path. Kernel, rights
and ABI unchanged. US-031 stays partial. phase3_complete stays false.
US-068/US-073, US-076, US-080 and US-081 stay partial. US-078 and US-097

Scope taken from the Lot 98 gaps (gap 1), in the order of the brief:
hsl() and hsla() as colours the reader paints, the turn, rad and grad hue
units, a real accumulate for animation-composition (told apart from add
where it matters, on transforms), the 0% and 100% keyframes a rule leaves
out composed with the animation's composition, and animation-timeline
(auto, none and a dashed name, parsed, cascaded, coordinated and stored).

A row is listed only when its code, tests and docs are in the branch.

## Scope

| Id | Feature | Before | After |
|----|---------|--------|-------|
| A | hsl() as a reader colour (Lot 98 gap 1) | an hsl() value was a valid registered <color> and interpolated, but color, background-color and the background shorthand dropped it (an hsl() end value or var() with an hsl() value painted nothing) | wf_cssprop_rgb24 gives the 24-bit colour of an opaque hsl() or hsla() (its alpha, clamped to 0..1, is 1): the text runs to the first ')', after it only spaces then the end, ';' or '!' may follow; letters in any case; each channel of CSS Color 4 hslToRgb (exact in fixed point, Lot 98) rounded half away from zero to 0..255. The reader's colour parser (color, background-color, the colour of the background shorthand, and so var() values) takes it; a colour with an alpha under 1 is still dropped (the reader paints no alpha). Gradient stops keep the Lot 90 check (no hsl(): the engine would not paint them). The background shorthand keeps its colour word under 32 bytes (Lot 90). Proof: test_lot99_color.c (300 reader colours), test_lot99_sheet.c (120 painted colours), test_lot99_reader.c (hue_units, hsl_paint), `make qemu-lot99` (#c99, #g99, #h99), `make qemu-lot98` (converted: #h98 at 2000ms is bg #0000ff) |
| B | Hue units turn, rad, grad (Lot 98 gap 1) | the registered <color> check took the letters of deg only, so hsl(0.5turn ...) was not a colour | the colour check takes the letters of grad, rad and turn inside hsl() and hsla() (not rgb()); the hue is any <angle> the reader knows: 1grad = 0.9deg, 1turn = 360deg, 1rad = 180 x 10^7 / 31415927 deg (the pi of the reader since Lot 91), rounded to 1/10000 deg like any angle, then taken modulo 360deg. Proof: test_lot99_color.c (220 interpolations and the reader colours, 155 with turn, rad or grad), test_lot99_reader.c (hue_units: 3.1416rad, 1.5708rad whose red channel 127.4991 rounds down, 1rad, -0.25turn, 400grad), `make qemu-lot99` |
| C | accumulate told apart from add (Lot 98 gap 1) | accumulate was add, and transforms were not additive (they replaced) | wf_cssprop_accumulate. On a <transform-list> (and a <transform-function>+ list) add is the list below followed by the value's list; accumulate pairs the functions in order (CSS Transforms 2 section 15): the same function with as many arguments sums its arguments (lengths, percentages and angles as add sums them, their mix as calc(); scale arguments as a + b - 1 with a percentage taken as its number / 100; the rotate3d() axis must be the same text), the tail of the longer list is kept (its pair is the identity); matrix(), perspective(), two other functions or another axis make the value replace the one below. A single <transform-function> (and each item of a <transform-function># list) has no one-function sum, so add replaces and accumulate pairs the two functions. The result is written into the room given; when it does not fit, the call gives 0 and the reader keeps the keyframe value uncomposed. Other types: accumulate is add (Web Animations 1 tells them apart only for these transforms here). Proof: test_lot99_accum.c (520 pairs, add and accumulate side by side), test_lot99_reader.c (accumulate_api, reader_transforms), test_lot99_sheet.c |
| D | Generated keyframes composed (Lot 98 gap 1) | the 0% and 100% keyframes a rule leaves out were filled with the value below, uncomposed | CSS Animations 2 (generate initial and final frames): such a keyframe takes the element's own value (its value before any animation) composed with the animation's composition, not a keyframe's own, on the value below; with replace it is the own value itself (Lot 98 took the stacked value below). A composite that does not combine leaves the own value. Proof: test_lot99_reader.c (generated_frames), test_lot99_sheet.c (300 sheets, most without 0% or 100%), test_lot98_sheet.c and test_lot98_reader.c (converted), `make qemu-lot99` (#sp99 25px at 500ms) |
| E | animation-timeline (Lot 98 gap 1) | not read | a comma list of auto, none or a dashed identifier (under 32 bytes, kept as written), one token per item; scroll() and view() are not taken (the declaration is dropped); initial and unset reset it; inherit is not taken. It is the tenth animation longhand (WF_CSSANIM_L_TIMELINE): cascaded on its own, reset to auto by the animation shorthand (CSS Animations 2: a reset-only sub-property), coordinated with the other lists and stored per animation (wf_cssanim_t.timeline and .tlname). The reader has no scroll or view timelines and no named timeline is ever defined, so an animation whose timeline is not auto has no effect; one whose name is a kept @keyframes is counted as idle, and the css-anim line gets " idle N" when N > 0. Proof: test_lot99_timeline.c (200 lists and 160 coordinations of ten longhands), test_lot99_reader.c (timeline_api, timeline_reader), test_lot99_sheet.c (idle counts), `make qemu-lot99` (#n99, css-anim ... idle 1) |

## Review points

1. Structure sizes: we_doc_t keeps 870824 bytes (< 1 MiB, webeng.c untouched). wf_site_t grows from 494572 to 496112 bytes (wf_site_node_t 1196 to 1204: one more longhand index, shorthand flag and rank for animation-timeline; the anim_idle counter). wf_cssanim_t grows from 72 to 108 bytes (timeline byte and a 32-byte tlname); wf_site_rule_t (1108) and wf_csstrans_t (68) keep their sizes.
2. Cascade kinds: animation-timeline is longhand slot 9 (WF_SITE_K_LONG0 + 9 = 38), so the five transition longhand kinds move from 38..42 to 39..43 (they are WF_SITE_K_LONG0 + WF_CSSANIM_LONGS + k, computed, never stored across builds); WF_SITE_ALONGS 14 -> 15. WF_CSSANIM_LONGS 9 -> 10.
3. New API: wf_cssprop_accumulate, wf_cssprop_rgb24, WF_CSSANIM_L_TIMELINE, WF_CSSANIM_TL_AUTO/NONE/NAMED, wf_cssanim_t.timeline and .tlname, wf_site_t.anim_idle; wf_cssprop_add of transform lists now concatenates (it replaced in Lot 98).
4. Choices: add on a <transform-list> (and <transform-function>+) is the concatenation, under then v (Web Animations 1); a single <transform-function> (and each item of a <transform-function>#) replaces on add; accumulate pairs functions in order, sums same-name functions with as many arguments (scale a + b - 1, a percentage as its hundredth, rotate3d() only about the same written axis), keeps the tail of the longer list, and replaces for matrix(), perspective() or two different functions; every other type accumulates as it adds. The generated 0%/100% keyframes take the element's own value composed with the animation's composition (never a keyframe's own) on the value below. animation-timeline is reset to auto by the animation shorthand; a non-auto timeline leaves the animation without effect, counted as idle only when its @keyframes exist. A reader colour must be opaque (hsla() with alpha < 1 is dropped as before).
5. Approximations: rad through the reader's pi (1800000000 / 31415927 deg, Lot 92); hues rounded to 1/10000 deg; accumulate results written into the caller's room, refused (keyframe value kept uncomposed) when they do not fit; no matrix decomposition, so matrix()/perspective() and mismatched functions replace; named timelines are stored but never resolve (the reader has no scroll or view timelines).
6. Converted tests (assertions changed, none weakened; each now checks the new behaviour):
    - test_lot98_reader.c: WF_CSSANIM_LONGS is 10 (was 9); the "add" check moves to WF_CSSANIM_L_COMPOSITION, and WF_CSSANIM_LONGS - 1 (now animation-timeline) refuses "add" and takes "none"; the filled-ends case is 80px (was 70px): the generated 0% is composed.
    - test_lot98_sheet.c (regenerated from scripts/lot98_animmodel.py, which now composes the generated frames through scripts/lot99_animmodel.py and skips non-auto timelines): 47 value lines change, all sheets whose rules leave out 0% or 100% with add or accumulate.
    - test_lot98_longs.c (regenerated, scripts/lot98_animgen.py): the coordination arrays have 10 entries (a trailing 0, animation-timeline unset); expected values unchanged. A 9-entry array would be read past its end.
    - scripts/lot97_animmodel.py: the colour check takes the letters of turn, rad and grad in hsl() (no generated line changed).
    - tests/scripts/test_qemu_lot98.py: at 2000ms #h98 must be painted bg #0000ff (Lot 98 refused any bg there: the hsl() end value is now a reader colour); the helper node_line, only used by that refusal, is removed.
7. Removed after the mutation runs (each shown equivalent, its mutant dropped): a trim of the arguments of a single <transform-function> (the matched value is already trimmed); the distinction of P and L argument kinds (both read as length-percentage: the syntax match already refuses a percentage where only a length is allowed, so the type is angle or length-percentage); the lower-casing and the cp_color check in wf_cssprop_rgb24 (cp_rgba is case-insensitive and checks the whole colour; a fuzz of 400000 hsl()/hsla() texts found no value taken by wf_cssprop_rgb24 that wf_cssprop_match refuses as <color>); clearing tlname for auto and none (it is meaningful for TL_NAMED only); the h/s/l letter test before the reader colour parser calls wf_cssprop_rgb24 (it checks the prefix itself; a refused value falls through to the other forms, which refuse it too); the keyframe copy before kf_compose and its write on code 1 (code 1 gives v itself). One mutant was dropped as equivalent by construction: taking the rotate3d() axis from v instead of under (they are the same text when the pair is summed). Tried and reverted: leaving the room of the ", " separator, of the rotate3d() axis and of the space between two accumulated functions unchecked. It is not equivalent: a long axis that does not fit was skipped (rotate3d(, 1, 0, 10deg)), and a pair that does not sum after a short room gave code 1 instead of 0. Every piece is checked again (the first failure, room or sum, decides, as in the model), and test_lot99_reader.c has witnesses for each.

## Not done (first gaps for lot 100)

1. Animations: a running clock and repaint (the clock is still a value set by "web-css time N"), transitions and animations of the reader's own properties (only registered custom properties animate), scroll and view timelines (scroll(), view(), scroll-timeline, view-timeline, timeline-scope) and the animation-range longhands, transition events; accumulate of matrix(), perspective() and of two different functions (CSS Transforms 2 interpolates them as matrices; this reader replaces).
2. Colours: no alpha in reader colours (a translucent hsl() or rgba() is still dropped), no hwb(), lab(), lch(), oklab(), oklch() or color(); hsl() in gradient stops.
3. Fonts: one font metric set (the 8x8 engine font); no lh/rlh/cap/ic units.
4. Gradients: conic children of vertical boxes (refused), background-clip: text, a clip or origin per layer, background-attachment, fetched background images (unchanged).
5. @property: no <frequency>, <ratio> or <flex>; more than 8 alternatives, 16 registrations or 127-byte values are refused (unchanged).
6. Autofill, PSL, NE2000, shaping, US-080 and US-081: unchanged (see docs/lot97_plan.md).
